ระบบวัดรอบเวลาการผลิต (Cycle Time)

สถานี LAYUP2 — ระบบตรวจจับด้วยกล้องบน Raspberry Pi

สำหรับ: พนักงานคุมสาย และหัวหน้ากะ เวอร์ชัน 1.0

สารบัญ

  1. ระบบนี้ทำอะไร
  2. จอแสดงผลทั้งสองจอ
  3. วิธีอ่านบอร์ด 40 นิ้ว
  4. วิธีอ่านแดชบอร์ด 7 นิ้ว
  5. การตั้งกล้อง (สำคัญที่สุด)
  6. การตั้งกะและทีม
  7. การหยุดสาย (Stoppage)
  8. การแก้ปัญหาเบื้องต้น
  9. ข้อจำกัดของระบบ

1ระบบนี้ทำอะไร

กล้องส่องลงมาที่สายพาน เราลากกรอบสี่เหลี่ยมคลุมจุดที่ชิ้นงานวิ่งผ่าน ทุกครั้งที่มีชิ้นงานผ่านกรอบนั้น ระบบจะจับเวลาไว้ แล้วบันทึกว่าเป็นผลงานของทีมไหนตามตารางกะ

สิ่งที่ระบบตอบให้ได้:

  • ตอนนี้ผลิตได้กี่วินาทีต่อชิ้น เทียบกับเป้าหมายแล้วเร็วหรือช้ากว่าเท่าไหร่
  • รอบเวลา ผันผวน มากแค่ไหน — สายนิ่งหรือเริ่มเพี้ยน
  • ทีม A, B, C ทีมไหนทำเวลาได้ดีที่สุด ทั้งรายวัน รายสัปดาห์ และรายเดือน
ไม่ต้องต่อสายเข้าเครื่องจักร

ระบบใช้กล้องมองอย่างเดียว ไม่ต้องต่อ PLC ไม่ต้องเดินสายเซนเซอร์ และไม่ต้องต่ออินเทอร์เน็ต — ข้อมูลทั้งหมดเก็บอยู่ในเครื่องที่หน้างาน

กราฟ CYCLE TIME (กราฟเส้น)

แสดงทุกรอบเรียงตามลำดับเวลา — นี่คือจุดที่มองเห็นความผันผวนได้ชัดที่สุด

  • เส้น x̄ = ค่าเฉลี่ย
  • เส้นประแดง UCL / LCL = ขีดจำกัดควบคุม จุดที่หลุดออกนอกเส้นนี้ ไม่ใช่ความผันผวนตามปกติ แต่แปลว่ามีอะไรเกิดขึ้นจริง ๆ ควรตามหาสาเหตุ
  • เส้นประเขียว target = เป้าหมาย
  • จุดสีแดงและใหญ่กว่าปกติ = รอบที่หลุดขีดควบคุม

รูปแบบกราฟที่ควรสังเกต:

ลักษณะกราฟมักแปลว่า
กระจายสม่ำเสมอรอบเส้น x̄สายนิ่งดี ปกติ
ค่อย ๆ ไต่ขึ้นเรื่อย ๆเครื่องมือเริ่มสึก หรืออุปกรณ์ร้อนขึ้น
กระโดดขึ้นเป็นขั้นแล้วค้างอยู่ระดับใหม่เปลี่ยนกะ เปลี่ยนวัตถุดิบ หรือเปลี่ยนการตั้งเครื่อง
ขึ้นลงเป็นจังหวะซ้ำ ๆมีอะไรบางอย่างเกิดขึ้นทุก ๆ กี่ชิ้น เช่น ต้องเติมของหรือเปลี่ยนถาด

กราฟ DISTRIBUTION (กราฟแท่ง)

แสดงการกระจายตัวของรอบเวลา

  • ยอดเดียว = กระบวนการนิ่ง เป็นแบบที่ต้องการ
  • สองยอด = สายกำลังทำงานอยู่ สองรูปแบบจริง ๆ มักเกิดจากมีการแทรกแซงบางชิ้นแต่ไม่ทุกชิ้น เช่น บางชิ้นต้องแก้ไขเพิ่ม — ข้อนี้มักเป็นสิ่งแรกที่ระบบช่วยให้เจอ

5การตั้งกล้อง (สำคัญที่สุด)

อ่านหัวข้อนี้ก่อนเชื่อตัวเลขทุกครั้ง

ระบบตรวจจับด้วยการเทียบความสว่างที่เปลี่ยนไปในกรอบ ทำงานเร็วและไม่ต้องสอนระบบ แต่มีข้อแลกเปลี่ยนคือ อะไรก็ตามที่ขยับอยู่ในกรอบ ระบบจะนับว่าเป็นชิ้นงาน ความแม่นยำจึงขึ้นอยู่กับการวางกล้องและแสงเป็นหลัก

สิ่งที่ควรทำ

  • ส่องกล้องลงตรง ๆ ที่สายพาน ให้ตั้งฉากมากที่สุดเท่าที่ทำได้
  • ลากกรอบให้กว้างกว่าชิ้นงานเล็กน้อย และอยู่ในสายพาน ไม่ล้ำขอบ
  • ถ้าบริเวณนั้นแสงน้อย ให้ติดไฟ LED แบบอยู่กับที่เพิ่ม
  • ดูค่า Occupancy ในหน้า Setup ขณะที่ชิ้นงานวิ่งผ่าน: ตอนสายพานว่างควรใกล้ 0% และตอนชิ้นงานผ่านต้องพุ่งเกินขีดสีแดงชัดเจน

สิ่งที่ต้องเลี่ยง

  • แสงแดดจากหน้าต่าง หรืออะไรก็ตามที่ทำให้เงาขยับ
  • คน มือ หรือรถโฟล์คลิฟท์ที่เดินผ่านกรอบ
  • ขอบสายพาน หรือราวกั้นที่สะท้อนแสง อยู่ในกรอบ

การปรับค่าละเอียด (แตะที่หน้า Setup)

ปรับเฉพาะเมื่อการนับผิดพลาดเท่านั้น ค่าที่ปรับจะบันทึกทันที

ค่าเพิ่มค่าเมื่อลดค่าเมื่อ
Enter ratio
(ปกติ 0.15)		 เงาหรือสัญญาณรบกวนทำให้นับเกิน ชิ้นงานเล็ก ระบบตรวจไม่เจอ
Exit ratio
(ปกติ 0.07)		 ระบบไม่ยอมมองว่าชิ้นงานออกจากกรอบแล้ว กรอบกะพริบว่างทั้งที่ชิ้นงานยังอยู่
Pixel threshold
(ปกติ 25)		 ภาพมีสัญญาณรบกวนหรือเป็นเม็ด สีชิ้นงานใกล้เคียงกับสีสายพานมาก
Dwell
(ปกติ 0.3 วินาที)		 มีการกะพริบสั้น ๆ แล้วถูกนับเป็นชิ้นงาน ชิ้นงานวิ่งเร็วจนระบบนับไม่ทัน
Exit ต้องน้อยกว่า Enter เสมอ

ช่องว่างระหว่างสองค่านี้คือสิ่งที่ป้องกันไม่ให้ชิ้นงานชิ้นเดียวถูกนับซ้ำสองครั้ง ถ้าตั้งให้ Exit สูงกว่าหรือเท่ากับ Enter ระบบจะแก้ค่าให้อัตโนมัติ

ตรวจสอบก่อนเชื่อตัวเลข

ใช้นาฬิกาจับเวลาจับด้วยมือ 20 ชิ้นติดกัน แล้วเทียบกับตัวเลขบนหน้าจอ นี่เป็นวิธีเดียวที่พิสูจน์ได้ว่าค่าที่ตั้งไว้เหมาะกับแสงและชิ้นงานจริงของเรา โดยปกติจะต้องปรับค่าอีกหนึ่งรอบหลังทดสอบ

6การตั้งกะและทีม

ทีม A, B, C ทำงานวันละ 3 กะ กะละ 8 ชั่วโมง รวม 24 ชั่วโมง ระบบคำนวณตารางกะให้เองอัตโนมัติ ไม่ต้องกรอกทุกวัน จะแตะแก้เฉพาะวันที่มีเรื่องผิดปกติเท่านั้น

แก้ไขเฉพาะบางวัน

ไปที่ Shifts → Calendar แล้วแตะที่วันที่ต้องการ จากนั้นเลือกทีมของแต่ละกะ

  • ช่องสีเหลืองขีดเส้นใต้ = วันที่ถูกแก้ไขแล้ว ไม่ได้ใช้ตารางอัตโนมัติ
  • เลือก — = ไม่มีทีมทำงานกะนั้น เช่น วันหยุด หรือหยุดสาย
  • ปุ่ม Back to rotation = ยกเลิกการแก้ไข กลับไปใช้ตารางอัตโนมัติ
เลือก "—" กับ ไม่แตะเลย ต่างกัน

เลือก — คือบอกระบบว่าไม่มีใครทำงานกะนั้นจริง ๆ
ส่วนวันที่ไม่ได้แตะเลย ระบบจะใช้ตารางหมุนเวียนอัตโนมัติตามปกติ

ถ้าตารางกะกรอกผิดย้อนหลัง

ระบบบันทึกชื่อทีมลงไปตอนที่ชิ้นงานผ่าน ดังนั้นการแก้ปฏิทินทีหลัง จะไม่ไปเปลี่ยนตัวเลขของเดือนที่แล้วโดยที่เราไม่รู้ตัว ถ้าต้องการให้แก้ย้อนหลังจริง ๆ ให้แก้ปฏิทินก่อน แล้วแจ้งช่างเทคนิคให้สั่งคำนวณใหม่ (คำสั่ง /api/shifts/recompute)

7การหยุดสาย (Stoppage)

ถ้าไม่มีชิ้นงานผ่านนานเกิน 5 นาที ระบบจะถือว่าเป็นการหยุดสาย ไม่ใช่รอบการผลิตปกติ

  • ไม่ถูกนำไปคิดค่าเฉลี่ย และไม่ถูกวาดลงกราฟ
  • เหตุผล: ถ้าเอาช่วงพักเที่ยงไปรวมด้วย กราฟจะถูกดึงจนอ่านความผันผวนจริง ๆ ไม่ออกเลย
  • แต่ยังเห็นได้ในป้ายบนแถบด้านบน ในหน้า Table และในไฟล์ CSV

8การแก้ปัญหาเบื้องต้น

อาการสาเหตุและวิธีแก้
หน้าจอขึ้น NO CAMERA สาย USB ของกล้องหลุดหรือหลวม ให้เสียบใหม่ ระบบจะกลับมาเองภายในไม่กี่วินาที
ไม่นับเลย ทั้งที่มีชิ้นงานผ่าน ค่า Occupancy ไม่เคยเกินขีดแดง ให้ลด Enter ratio หรือ ลด Pixel threshold หรือลากกรอบให้เล็กลงเพื่อให้ชิ้นงานกินพื้นที่ในกรอบมากขึ้น
นับซ้ำ ชิ้นเดียวเป็นสองชิ้น เพิ่มระยะห่างระหว่าง Enter กับ Exit (ลด Exit ลง) หรือเพิ่มค่า Dwell
นับมั่ว ทั้งที่สายพานว่าง มีอะไรขยับอยู่ในกรอบ เช่น เงา คน หรือแสงแดด ให้ย้ายกรอบก่อน ถ้ายังไม่หายค่อยเพิ่ม Pixel threshold
ค้างที่คำว่า PRODUCT ตลอด แสงเปลี่ยนไปจากตอนที่ระบบจำภาพพื้นหลังไว้ ระบบจะแก้ตัวเองภายใน 5 นาที หรือกด Save ROI ใหม่เพื่อให้แก้ทันที

9ข้อจำกัดของระบบ

ระบบนับชิ้นที่ผ่าน ไม่ได้ตรวจคุณภาพ

ระบบนี้วัดช่วงเวลาระหว่างชิ้นงานที่ผ่านจุดหนึ่งบนสายพาน ซึ่งตรงกับความหมายของความผันผวนของรอบเวลาพอดี แต่ไม่ใช่ระบบตรวจสอบคุณภาพ

  • แยกของดีกับของเสียไม่ได้
  • ชิ้นงานสองชิ้นที่ติดกันสนิท อาจถูกนับเป็นชิ้นเดียว
  • ถ้าสายติดขัดจนหยุดนาน จะถูกบันทึกเป็นการหยุดสาย ไม่ใช่รอบการผลิต
  • ข้อมูลเก็บไว้ 90 วันย้อนหลัง เกินจากนั้นระบบจะลบทิ้งอัตโนมัติ — ถ้าต้องการเก็บนานกว่านั้นให้กด CSV ดาวน์โหลดไว้เป็นระยะ
